# Implementation decision log

Decisions made during implementation on 2026-10-16 (America/Los_Angeles).

1. **Single runtime:** Python 3.12 with NumPy/SciPy for fitting and CPU PyTorch for both ML paths. Exact direct dependencies and the resolved environment are committed. JAX is historical inspiration, not a second required environment.
2. **Source pins:** course main `86fb86c62108cae88a92f75b0f7268a9130a0aec`; MiniHEP `76cfa28c433d1f3e9ac95c0102974a55b37de54d`; benchmark `f6e47e6ce32bc9e40162b7238ff1933c5d182e2a`. These were resolved using Git on this date. No code license was found in the inspected source inventories. Reimplement the published interfaces and modeling concepts; retain attribution and do not imply permission to redistribute their code.
3. **Versioned migration:** dataset-v1 extends the benchmark table with stable event IDs and explicit train/validation/template partitions. Submission-v1 retains the benchmark `pois` result interface; score-v1 documents intentional differences. Known 125 GeV mass is fixed; mass fitting is an extension.
4. **Working data without external checkout:** ship a compact, deterministic synthetic teaching sample with explicit provenance, generation seed and checksums. It is a surrogate, not a detector simulation or an ATLAS measurement. Provide an independent ROOT conversion for authorized original data. Do not relabel synthetic events as ATLAS. A real ATLAS workshop is conditional on instructor verification of redistribution rights and sample provenance.
5. **Leakage:** separate simulation partitions before training/scaling; reserve partition 2 exclusively for templates; generate pseudo-data independently. Preserve event identity and reject duplicate kinematics crossing partitions. Rescale template yields after reserving the holdout; do not fit preprocessing to data or validation.
6. **Statistical scope:** Poisson templates, Gaussian 10% background constraint, signed best-fit mu and nuisance-profiled delta-NLL intervals. Discovery is one-sided. Finite simulation statistics and detector systematics are excluded in this short baseline and must be discussed when interpreting calibration.
7. **Safety and deployment:** no push, repository creation, issue creation, secrets mutation, or deployment during this local implementation. Hosted scoring is opt-in and fails closed until Docker isolation and workshop rehearsal have passed. The environment currently lacks GitHub CLI and Docker, so those live acceptance gates cannot truthfully be marked complete using mocked tests.
8. **Delegation:** the user requested GPT-6 Luna at high reasoning effort. Three such agents own ML, evaluation, and documentation; the senior agent owns integration, core measurement, source audit, and final verification.
9. **Public versus sealed evidence:** local suites may publish per-case truth and plots. Hosted leaderboards publish aggregates only. Seed and truth never enter sandbox mounts or student logs; no privileged workflow runs the submitted process directly.

Further decisions and verification results are appended below as integration proceeds.

10. **ROOT units resolved by inspection:** the pinned reduced ROOT table has pt and MET already in GeV, energy branches in MeV, and absent jet pt=-7. The converter preserves pt/MET, ignores E in favor of the massless canonical conversion, and replaces absent jets with zeros. Input SHA256: `ce864039e24cf0c2b73462e03179419f5ca5416bc813e5b7dab80dceb4a7ed08`. Conversion/load/fit were run locally on all 600,000 source rows; the public mu=1 pseudo-data result was 0.873 ± 0.116 with the initial fit settings (a validation observation, not an acceptance threshold). No ROOT file is committed.
11. **Seal input identities:** observation event IDs are local sequential numbers, independent of the generation seed. Encoding a seed into IDs would reveal the sealed generator state and overflow int64 for HMAC-derived seeds. A regression test covers a full unsigned 64-bit seed. Sealed inputs contain neither truth nor seed metadata.
12. **Sparse template calibration:** a 24-case local study (seeds 710–733, mu cycling 0/1/1.5, beta=1) exposed a defect in the initial 7×6 mass template with epsilon-only smoothing: RMS 0.1434, pull width 1.3596, and 1 false discovery in 8 null cases. The final 5×4 baseline and half a typical MC event pseudocount per bin gave RMS 0.1011, pull width 1.0113, and 0/8 null discoveries on the same study. This regularization is fixed before data inspection. It approximates finite-MC tail handling, not a full simulation-statistics nuisance model. The small null sample cannot establish a rare-event rate.
13. **Local checks execute the starter:** `higgslab check` now validates the actual submission entrypoint twice as well as the trusted baseline. On Windows it runs the equivalent starter `analysis.py`, since the available WSL Bash is inaccessible. Custom shell entrypoints need the documented Linux/Docker rehearsal. Docker's client exists but its engine is not running, so actual Docker tests remain unverified here.
14. **License scope:** MIT covers the newly written HiggsLab code, prose, and independently generated toy data only. Linked original code and data retain their own rights. No license for those sources is inferred.
15. **Final evaluator review:** default team identity is the public fork owner's account, avoiding collisions when many forks share a name. The owner claims the team/repository binding; later comments must come from that account. Submission cutoff uses GitHub's comment creation timestamp, so queue delays do not reject timely submissions. Cache identity includes the seed, trusted implementation fingerprint and cohort; prior suites are separated from current rankings and final selection.
16. **Bounded execution and collection:** only the submission subtree is fetched/exported. A detached, read-only, networkless container keeps bounded tmpfs output alive; submitted code runs as an unprivileged UID. A separate root extractor opens only the fixed result path with no symlink following and a 100 kB bound. Student stdout/stderr and Docker logging are discarded. A 25-minute aggregate budget bounds a 30-case submission in addition to per-case limits. Actual isolation remains a deployment gate because Docker's engine was unavailable.
17. **Operational sequencing:** setup, site preview and live submissions are distinct states. `init` preserves an existing seed and requires a matching passing isolation report to open submissions. `finalize` closes submissions and dispatches a fresh pass on the same suite; `archive` waits for that requested pass. The local implementation performs no GitHub mutation. Local browser fixtures demonstrated Refresh/polling and exact commit links; they are not presented as a hosted rehearsal.
18. **Completion evidence:** 47 Python tests pass (one Windows-only symlink skip), four JavaScript tests pass, both notebooks execute, strict docs/links/workflow syntax checks pass, and the built wheel passes the starter check in a fresh environment. `IMPLEMENTATION_STATUS.md` records local evidence and the live GitHub/Docker/Binder/licensing gates that cannot be honestly marked complete here.
19. **Cross-platform byte contracts:** force LF for tracked text and explicitly write generated metadata with LF, so Git checkout conversion cannot invalidate dataset checksums or turn shell scripts into CRLF executables. NPZ and PNG files remain binary. The final public metadata/checksums were regenerated after this correction.
