# Data and provenance

## What ships in the starter

The current `datasets/public` sample is a **synthetic teaching surrogate, not ATLAS data and not a detector simulation**. Its events are generated by the HiggsLab toy generator from simple signal-like and background-like distributions. The process labels, yields, and event shapes exist to exercise software and statistical concepts. They must not be described as public ATLAS events, a reproduction of an ATLAS result, or a measurement of nature.

The `dataset-v1` files follow a compact event-table contract:

| File | Role |
| --- | --- |
| `data/events.npz` | Events to analyze; labels are not supplied to the student scoring path. |
| `mc/pool.npz` | Labeled training, validation, and template samples. |
| `mc/pool_meta.json` | Schema, units, teaching origin, process labels, expected yields, and split definitions. |
| `checksums.json` | SHA-256 values for generated files, for local integrity checks. |

The sample columns include two leptons and up to two jets with `pt`, `eta`, and `phi`, MET magnitude and direction, lepton charges and types, and jet multiplicity. Missing jet slots are zero padded. `event_id` identifies events within a generated dataset. Training partitions are `0`, validation `1`, and template `2`; event identity and partition metadata are excluded from model inputs. Training-only preprocessing should use the training partition. The current sample generator is deterministic for a fixed seed.

The exact sample files may be generated locally with `higgslab generate`. Consult their `pool_meta.json` and the versioned schema code for the values shipped in your checkout; do not infer provenance from familiar process numbers or column names.

## Adapting a ROOT source responsibly

An optional preparation script, `scripts/prepare_root.py`, handles the reduced course ROOT schema. It selects events with exactly two leptons and positive `mcWeight`; source `pt` and MET values are already in GeV, while `lep_E` and `jet_E` are in MeV. The script ignores energy branches, preserves GeV `pt`/MET, and uses massless four-vector reconstruction in downstream feature code. Missing jet slots use the sentinel `pt = -7`; the converter turns those slots into zero padding. Never blanket-divide `pt` or MET by 1000.

The ROOT preparation command requires the `dev` extra and a source file already obtained under its own redistribution terms:

```bash
uv run python scripts/prepare_root.py INPUT.root output/root-validation --seed 42
uv run higgslab check --dataset output/root-validation --output output/root-check
```

It records the input checksum and course source commit in metadata. It draws a disjoint pseudo-data sample from its held-out source rows, so source rows are not reused across the MC pool and pseudo-data. The output identifies its origin as course reduced ATLAS simulation, records benchmark yields, and explicitly requires the instructor to establish the release and license before redistribution. This optional derived sample does not change the default generated public sample, which remains a synthetic teaching surrogate. A ROOT-to-table converter must document and validate every conversion:

1. Identify the actual tree, branch names, units, object ordering, selection, and event identifiers from the source file and its documentation.
2. Keep already-GeV `pt` and MET fields in GeV. Convert energy branches only if they are actually used, and convert their MeV units exactly once. Handle source missing-object sentinels before padding.
3. Treat the MET proxy according to the source definition. Do not label a proxy as measured MET unless its construction supports that claim.
4. Preserve process labels and event weights as supplied. Document cross sections, luminosity, filtering, and normalization before comparing yields.
5. Check zero padding, array lengths, finite values, labels, weights, unique event IDs, and checksums. Keep train, validation, and template partitions disjoint by event identity, including derived copies.
6. Record source URLs, exact source commits, file checksums, preparation code, license, and any permission needed to redistribute derived or original data.

The optional ROOT preparation path is separate from the synthetic public sample and does not regenerate it. The course and benchmark projects are references for a future documented migration, not evidence of the synthetic sample's provenance.
