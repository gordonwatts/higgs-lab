# Learn from a small labeled sample

The student core asks whether a fixed pretrained representation helps when labels
are scarce. Compare a frozen MiniHEP encoder plus its small discrimination head
with the engineered-feature MLP, using exactly the same 720 labeled events
(10% of the 7,200 partition-0 events). This compares complete approaches; their
different inputs and architectures prevent isolating the benefit of pretraining.

## Student core: load, adapt, measure

From the repository root, install the CPU ML dependencies once, then run:

```powershell
uv sync --extra ml
uv run python solutions/run_low_label.py
```

This loads the instructor-provided `solutions/models/encoder.json`, trains two
small heads for four epochs, and evaluates six generated measurement cases.
No encoder pretraining is required. On the reference CPU the model training took
under two seconds and the complete core/control reference recipe took about ten
seconds; hardware and dependency startup affect wall time.

Read `output/low-label/report.json`. Each model reports held-out validation AUC
and the existing suite diagnostics: `mu_precision` (mean fitted uncertainty),
`mu_bias`, `mu_recovery_slope`, `mu_recovery_intercept`, `pull_mean`, `pull_width`,
`mu_rms_residual`, and `recovery_fraction`. Compare both precision and recovery/
calibration. AUC diagnoses discrimination; a higher AUC does not guarantee a more
precise or better calibrated measurement. Six synthetic cases provide limited
evidence, especially for pull widths and recovery slopes.

Change the labeled budget with **either** `--label-fraction 0.05` **or**
`--label-count 360`; change its reproducible selection with `--subset-seed 17`.
Selection uses fixed per-class permutations and proportional rounded counts,
with at least one event from each class. Increasing budgets gives nested subsets.
The report and exported models record the exact selected row indices, count,
fraction, seed, and selection method. Both classifiers use identical rows.

The partitions stay fixed:

| Partition | Role |
| --- | --- |
| 0 | All 7,200 events form the unlabeled pretraining pool; only the chosen 720 labels train the downstream classifiers. |
| 1 | Fixed held-out validation AUC and loss diagnostics; no tuning or parameter updates. |
| 2 | Fixed simulation templates for the common measurement fit. |

The checkpoint token scaler uses only partition-0 vectors. The feature MLP scaler
uses only the chosen labeled rows. Validation/template labels never select the
subset or fit preprocessing/model parameters. The recipe uses fixed epochs and
does not choose checkpoints or settings using validation results. Template labels
are used only for their intended signal/background template construction.

## Optional: isolate pretraining with a matched transformer

```powershell
uv run python solutions/run_low_label.py --transformer-control --output output/low-label-control
```

The extra `scratch` and `finetuned` arms share the architecture, token inputs,
head, exact checkpoint preprocessing, labeled rows, seed, four adaptation epochs,
optimizer, and validation/template partitions. The scratch arm reads preprocessing
metadata from the checkpoint but discards its weights and never calls pretraining;
its model metadata records `weights_loaded: false`. The fine-tuned arm loads the
checkpoint weights and adapts all encoder/head parameters. Head initialization
and adaptation randomness are matched. This comparison addresses pretraining
more directly than comparing the MLP and frozen encoder.

Checkpoint metadata reports reconstruction epochs, event count, batch size,
optimizer steps, and elapsed seconds. Each arm separately reports adaptation
epochs, batch size, optimizer steps, and elapsed time including model I/O. The
pretraining cost is additional: matching adaptation epochs does not match total
compute. Scratch performs zero pretraining steps. Reported checkpoint compute is
the historical instructor cost, not a cost incurred by loading it.

`solutions/models/low-label-reference.json` records a six-case reference run of
all four arms, generated by the command above. On this synthetic sample the MLP
had AUC 0.83, frozen encoder 0.54, scratch transformer 0.55, and fine-tuned encoder
0.62. These small, short fits show no guaranteed pretraining advantage and are not
evidence about ATLAS performance. The recipe generates its model artifacts,
case datasets, individual fit results, and aggregate report inside the output
directory; no checked-in report is overwritten.

## Optional instructor pretraining and independent extensions

To reproduce the instructor checkpoint:

```powershell
uv run higgslab pretrain datasets/public output/encoder.json --epochs 4
uv run python solutions/run_low_label.py --checkpoint output/encoder.json
```

The versioned JSON checkpoint carries architecture, dropout, token-contract
version, complete encoder weights, asinh scaling, seed, reconstruction history,
training-pool fingerprint, PyTorch version, and compute metadata. It is not a
classifier submission. Reconstruction uses no labels and no held-out inputs;
its diagnostic loss also uses partition 0. Loading validates the format,
architecture, scaling and finite weights. Adaptation checks the partition-0
fingerprint to prevent accidentally using a checkpoint from a different pool.
Cross-task checkpoint reuse is outside this exercise. With the pinned runtime,
weights and preprocessing reproduce deterministically; elapsed-time metadata
varies, so regenerated checkpoint file hashes can differ.

The ordinary `higgslab train` command also accepts `--checkpoint`,
`--label-fraction`/`--label-count`, and `--subset-seed` for individual experiments.
Its historical default remains 100% labels; the short recipe defaults to 10%.
Training frozen/finetuned without a checkpoint retains the original pretrain-then-
adapt behavior. Fine-tuning, nested 1%/5%/10%/100% budget studies, repeated seeds,
and instructor pretraining are independent optional extensions. The student core
does not require running any of them. Use separate output directories per run.
